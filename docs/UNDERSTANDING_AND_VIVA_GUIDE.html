What Did We Build & Why Does It Matter?

The Real-World Problem We Solved

In college and university hostels, infrastructure maintenance is broken. When a bathroom tap bursts, an electrical socket sparks, or the WiFi router in Wing B goes down, students typically write their complaints in a physical register at the security desk or post in unstructured WhatsApp groups.

The consequences: Complaints get lost, identical issues get raised multiple times by roommates, electricians and plumbers have no prioritized work order, and the Hostel Warden has zero visibility into how long repairs actually take.

FixMyHostel (The Product)

  • Student Portal: Residents submit geo-tagged complaints with photos, receive an atomic daily token (resetting at midnight IST), track ticket progress in real-time, and rate service quality (1–5 stars).
  • Staff Live Queue: Maintenance staff work an automated, priority-sorted queue: Critical → High → Medium → Low. Higher severity and older tickets bubble to the top automatically.
  • Warden Executive Dashboard: Real-time Service Level Agreement (SLA) metrics, turnaround duration charts, appliance failure hotspots, and technician efficiency metrics.

The DevOps Integration (The Curriculum)

Instead of building a toy app for each lab experiment, FixMyHostel ties all first 7 experiments of the ASD&D syllabus into one production stack:

  • Exp 1: Git Version Control (16 branches, 15 PRs, semantic tags)

The DevOps Toolchain: Core Concepts Explained From Scratch

Git Git & GitHub (Version Control)

What is it in plain English?

A Distributed Version Control System (DVCS) that records every historical change made to code. Think of it as an infinite "undo" button plus a parallel dimension machine where multiple developers can work on separate features without overwriting each other's work.

Key Concepts:
  • Branch: An isolated timeline of development (e.g. feature/FMH-2-database-schema).
  • Commit: A permanent cryptographic snapshot of staged changes with an author and message.
  • Pull Request (PR): A proposed merge from a feature branch into main, requiring code review and CI verification.
  • Merge Commit: Combines branch histories into main while preserving individual commit lineage.
How we used it in FixMyHostel:

We maintained 16 branches, 15 pull requests, and semantic version tags (v1.0.0 to v1.0.2). Developers never pushed to main directly.

🐳 Docker (Containerization)

What is it in plain English?

A virtualization tool that packages an application along with its exact dependencies, libraries, Node.js version, and OS configuration into a single portable unit called a container. It permanently eliminates the classic excuse: "It works on my machine, why not yours?"

Key Concepts:
  • Image vs Container: An image is the blueprint (read-only); a container is the live running instance (writable layer).
  • Multi-stage build: Compiling dependencies in a heavy build stage, but copying only minified artifacts to a lightweight production runtime (keeps images small and fast).
  • Healthcheck: Docker regularly executes an internal check (e.g., wget /api/ops/health) to ensure the service is truly responding.
How we used it in FixMyHostel:

Both api (Node 20 Alpine) and frontend (Nginx Alpine) have multi-stage Dockerfiles executing as unprivileged non-root users.

🐙 Docker Compose (Multi-Container Orchestration)

What is it in plain English?

When an application consists of multiple containers (frontend, API, database, cache, monitoring), running 7 individual docker run commands with complex port and network flags is error-prone. Docker Compose declares the entire multi-service stack in a single docker-compose.yml file.

Key Concepts:
  • Services: The containers that make up the app (frontend, api, mysql, redis, etc.).
  • Bridge Network: An isolated virtual network (fmh-network) where containers talk to each other by name (e.g. http://api:5000).
  • Named Volumes: Persistent storage that survives container deletions (e.g. mysql-data).
  • Health-gated startup: Using depends_on with condition: service_healthy so the API never starts before MySQL accepts queries.

⚙️ Jenkins (Continuous Integration & Deployment)

What is it in plain English?

An open-source automation server that acts as a tireless robot. Whenever code is committed, Jenkins automatically checks it out, installs dependencies, runs unit tests, lints the code, builds Docker images, and deploys the update to production.

Key Concepts:
  • CI (Continuous Integration): Automatically building and testing every commit so bugs are found within seconds.
  • CD (Continuous Deployment): Automatically releasing verified code straight to the production server.
  • Pipeline-as-Code: Declaring the entire build and test lifecycle inside a version-controlled Jenkinsfile.
  • Automated Rollback: If a deployment smoke test fails on main, Jenkins automatically re-deploys the last known good version.

📋 Jira & Agile Scrum (Project Management)

What is it in plain English?

Instead of waterfall development (spending 6 months writing specifications before writing code), Agile Scrum breaks work into short 1- to 2-week iterations called Sprints. Jira is the industry-standard software board for tracking this lifecycle.

Key Concepts:
  • User Story: A feature written from the user's point of view: "As a student, I want to upload a photo of the leak so the plumber brings the right tools."
  • Story Points: Fibonacci numbers (1, 2, 3, 5, 8) representing relative effort and complexity.
  • Scrum Board: Visual Kanban columns: To Do → In Progress → In Review → Done.
  • Definition of Done (DoD): Criteria required before a card can be moved to Done (e.g., green Jenkins build + passing unit tests).

🔥 Prometheus (Time-Series Metric Scraping)

What is it in plain English?

A pull-based time-series database designed for real-time monitoring. Every 15 seconds, Prometheus reaches out to our API endpoint (/api/ops/metrics), downloads numeric measurements (counters, gauges, latencies), and timestamps them.

Key Concepts:
  • Pull vs Push: Rather than the application sending millions of logs out, Prometheus pulls (scrapes) a structured metrics endpoint on a timer.
  • Metric Types:
    • Counter: A number that only goes up (e.g. complaints_total, total HTTP requests).
    • Gauge: A number that goes up and down (e.g. active tickets in queue, memory usage).
    • Histogram: Tracks durations and bucket distributions (e.g. HTTP request latency in milliseconds).
  • PromQL: Prometheus Query Language used to calculate rates and 95th percentile latencies (e.g. histogram_quantile(0.95, rate(...))).

📊 Grafana (Metrics Visualization Dashboards)

What is it in plain English?

Prometheus stores raw numbers; Grafana turns those numbers into beautiful, interactive visual dashboards. It connects to Prometheus as a datasource and renders real-time line charts, gauge dials, bar charts, and status indicators.

Key Concepts:
  • Datasource: The backend where Grafana gets its data (pointing to http://prometheus:9090).
  • Dashboard Provisioning: Instead of manually clicking buttons in the UI to draw charts, Grafana loads our pre-built fixmyhostel.json dashboard automatically on startup.
  • Our 12 Panels: Displays Request Rate, Error Rate, p50/p95 Latency, Total Complaints, Active Queue, and Node.js Event Loop Lag.

🛡️ Nagios Core (Active Availability & Host Monitoring)

What is it in plain English?

While Prometheus watches trends over time, Nagios asks: "Is this specific server or port alive right this second?" Nagios actively sends TCP pings and HTTP requests to test if containers and host ports are UP or DOWN.

Key Concepts:
  • Plugin Architecture: Nagios uses small external executables (check_http, check_tcp, check_ping) that return an exit status: 0 = OK, 1 = WARNING, 2 = CRITICAL.
  • Soft vs Hard State: If a service check fails once, it enters a Soft state (retried 3 times). If it fails 3 consecutive times, it becomes a Hard state and alerts are triggered.
  • NRPE (Nagios Remote Plugin Executor): An agent installed on remote hosts allowing Nagios to inspect disk usage, CPU load, and running processes across the network.

Supporting Infrastructure Glue

Nginx Alpine

Acts as a reverse proxy on Port 3000. It serves pre-compiled static React assets and transparently proxies all /api/* calls to the Express backend, completely preventing browser CORS errors.

Redis 7 Alpine

An ultra-fast in-memory key-value cache. It handles atomic sequence increments (INCR token:2026-10-13) for daily tokens and caches student ticket counts with a 60-second TTL.

MySQL 8.0 Relational Store

The ACID-compliant relational database. Stores users, complaints, and student feedback with foreign key cascading and multi-column indexes across status and raised_at.

Under the Hood: How FixMyHostel Works End-to-End

1. The Complaint Lifecycle & State Machine

The system strictly enforces an automated state machine. Invalid state transitions (such as trying to mark a ticket RESOLVED without accepting it first) are blocked at the API level with an HTTP 400 Bad Request error:

[Student Files Ticket]
  ↓
RAISED (Token assigned, e.g. T-044)
  ├── [Student cancels] → CANCELLED
  └── [Staff clicks Accept] → ACCEPTED (Technician assigned)
        ↓ [Staff starts repair]
      IN_PROGRESS (Work underway)
        ↓ [Staff enters resolution notes]
      RESOLVED (Timestamped, ready for feedback)
        ↓
[Student Submits 1–5 Star Rating & Review]

2. Dual-Store Architecture (Why our tests run in 500ms)

One of the architectural triumphs of this project is the Dual-Store Pattern.

  • Production Mode (MySQL + Redis): In live Docker Compose mode, api/server.js initializes connections to the real MySQL database pool and Redis caching client.
  • Testing Mode (In-Memory Map Store): When Jenkins or a developer runs npm test, Jest initializes Express using an in-memory Map store. It creates mock arrays for users and complaints in RAM.
  • The Benefit: All 40 backend unit tests run in less than 800 milliseconds without needing MySQL or Redis to be booted! This makes the Jenkins CI pipeline blazingly fast and deterministic.

3. The End-to-End DevOps Feedback Loop (The "Bug FMH-15" Story)

Important viva story to tell the teacher: This proves you didn't just write code, but used DevOps practices to catch and fix a real bug!

After releasing version 1.0.8, our Nagios monitoring dashboard flagged the fmh-frontend container as UNHEALTHY, even though students could open the website in their browser.

Root Cause: Inside the minimal Alpine Linux container, the command wget http://localhost:80/ resolved localhost to the IPv6 address ::1 first. However, Nginx was configured to listen only on IPv4 (0.0.0.0:80), causing the internal healthcheck to fail with a connection refused error.

DevOps Resolution:
1. Logged bug as FMH-15 in Jira.
2. Created Git branch fix/FMH-15-frontend-healthcheck.
3. Changed the health probe target from localhost to 127.0.0.1 explicitly.
4. Jenkins CI automatically triggered, ran 46 tests, rebuilt the container, and verified the fix.
5. Merged PR #15 to main, which automatically deployed release v1.0.9. Nagios immediately turned green!

Anticipated Viva Questions & Model Answers
What is the difference between Prometheus and Nagios? Why do you need both?
Prometheus follows a time-series metric model (pull-based). It records numeric metrics over time (e.g., request rates, p95 latencies, memory usage) so you can analyze trends and patterns. Nagios follows a state-based availability model. It runs active checks every few minutes to ask: "Is this port or process alive right now?" and triggers immediate alerts if a service transitions to a Hard CRITICAL state. We use Prometheus to understand performance trends and Nagios to ensure host and container uptime.
Why did you use Docker Compose instead of plain Docker commands?
FixMyHostel consists of 7 interdependent services (frontend, backend, database, cache, and 3 monitoring tools). Running individual docker run commands would require repeating complex port bindings, volume mounts, and network configurations manually. Docker Compose allows us to define the entire multi-container architecture declaratively in a single docker-compose.yml file, spin it up with a single command (docker compose up -d), and enforce health-gated startup dependencies (e.g. API waits for MySQL to be healthy).
How does your CI/CD pipeline prevent broken code from reaching production?
Our Jenkins Declarative Pipeline executes automated gates:
1. Linting: Verifies syntax and coding standards.
2. Automated Tests: Runs 46 unit and integration tests (Jest + Vitest). If even a single test fails, the build halts immediately.
3. Smoke Verification: On main, after deploying the new containers, a bash smoke script polls /api/ops/health to ensure the container is UP and running the exact new version.
4. Rollback Block: If smoke testing fails, the pipeline's post { failure } block automatically redeploys the last recorded good version.
What is a multi-stage Dockerfile and why did you use it?
In a multi-stage build, the Dockerfile is divided into multiple FROM stages. In the first stage (Builder), we install build tools, compilers, and dependencies (like npm ci and vite build). In the final stage, we start from a clean, minimal Alpine image and copy only the compiled production artifacts (e.g., minified JS and CSS). This reduces our frontend container image size from over 350 MB down to just 25 MB, minimizing attack surface and speeding up deployments.
How does Redis prevent race conditions when two students file a complaint at the exact same millisecond?
Redis is single-threaded and executes commands atomically in memory. When generating daily token numbers, we use the Redis command INCR token:YYYY-MM-DD. Because INCR is an atomic primitive, it guarantees that even if 50 students submit complaints concurrently in the same millisecond, each request receives a sequentially unique integer (T-001, T-002, etc.) with zero race conditions or database locks.
What is PromQL? Can you give an example of a query used in your Grafana dashboard?
PromQL stands for Prometheus Query Language. It is used to filter and aggregate time-series data. An example from our Grafana dashboard is calculating the 95th percentile API response latency:
histogram_quantile(0.95, sum(rate(http_request_duration_seconds_bucket[5m])) by (le))
This calculates the maximum response time experienced by 95% of requests over a 5-minute rolling window.
Why does your backend use the Dual-Store architecture?
In production, the backend interacts with MySQL 8.0 and Redis. However, running MySQL and Redis during automated test runs introduces network latency, database setup/teardown overhead, and flaky tests. By designing an abstract store interface with both a mysqlStore and an in-memory memoryStore, our 40 backend Jest tests run purely in RAM in under 800 milliseconds inside Jenkins without needing an external database.
What are the columns on your Scrum board and what is your Definition of Done?
Our Scrum board has 4 columns: To Do, In Progress, In Review, and Done. Our team's Definition of Done (DoD) requires that:
1. Code was developed on an issue branch (e.g. feature/FMH-2-database-schema).
2. A Pull Request was raised and reviewed.
3. The Jenkins multibranch CI build passed all 46 automated tests with JUnit reporting.
4. The feature was verified live in the running container environment.
